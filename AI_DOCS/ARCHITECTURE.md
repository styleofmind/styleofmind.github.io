# Архитектура сайта

## Модель проекта

Это статический сайт, опубликованный через GitHub Pages. HTML-файлы страниц используют собственные CSS, JavaScript и локальные изображения. По умолчанию нет этапа сборки: редактируемые файлы непосредственно обслуживаются как статические ресурсы.

## Корень репозитория

- `index.html` — главная страница-каталог концептов.
- `концеп расстановки/` — варианты сайта о системных семейных расстановках.
- `концеп лендинга/` — отдельные варианты редакционного лендинга.
- `catalog-screenshots/` — оптимизированные скриншоты для каталога.
- `tools/site_tools.py` — локальные инструменты предпросмотра и аудита.
- `check_site.bat`, `open_site_local.bat` — запуск проверок и локального предпросмотра в Windows.
- `requirements-audit.txt` — зависимости локального аудита, не зависимости публикуемого сайта.
- `PROJECT_CONTEXT.md`, `PLAN.md`, `LOCAL_PREVIEW.md`, `AUDIT_TOOLING.md` — контекст, план выпуска и инструкции для проверки.
- `robots.txt`, `sitemap.xml`, `404.html` — технические страницы и правила индексации.

## Каталоги концептов

Актуальная карта версий хранится в `PROJECT_CONTEXT.md`. Не восстанавливать устаревшие пути только потому, что они упомянуты в старых коммитах. В частности, `концеп расстановки/concept-2/v2.2/` — снятый с эксплуатации URL; актуальная перенесённая версия находится в `концеп расстановки/concept-3/v3.1/`.

Страница версии обычно состоит из:
- `index.html` — структура, тексты, ссылки, метаданные и подключение ресурсов;
- `styles.css` — стили конкретной версии;
- `app.js` — интерактивность, если она нужна;
- локальных каталогов изображений/шрифтов/других ресурсов, перечисленных в HTML и CSS.

Не считать все версии идентичными: пути ресурсов, состав секций, поведение и оформление могут отличаться.

## Концепт расстановки 1.1

Каталог: `концеп расстановки/concept-1/v1.1/`.

### Hero и видео

- Hero находится в начале `index.html`, внутри `main`.
- Контейнер визуального блока: `.hero-art`; декоративный слой: `.hero-halo`.
- Превью: `.hero-video-preview`, картинка: `.hero-video-poster`, кнопка Play: `.hero-video-play`.
- Постер загружается с Kinescope по адресу `https://kinescope.io/eWhaw3CwffKhViyhnev9AA/poster.jpg`.
- `app.js` слушает клик по превью и заменяет его на iframe `https://kinescope.io/embed/eWhaw3CwffKhViyhnev9AA?autoplay=1`.
- `styles.css` задаёт размер и позиционирование hero-видео, постера и кнопки. При редизайне сохранять предсказуемые размеры контейнера и не допускать скачка макета.
- Текущий iframe намеренно создаётся после клика, чтобы не загружать видеоплеер до взаимодействия пользователя.

### Навигация и ссылки

- Внутренние якоря связывают навигацию с секциями текущей страницы.
- Контактная запись ведёт в Telegram; не менять URL и параметры без запроса.
- Внешние ссылки, открывающиеся в новой вкладке, должны сохранять безопасные атрибуты вроде `rel="noopener noreferrer"`.

## Стили и адаптивность

- Сохранять мобильную и настольную композиции отдельно, если текущий CSS задаёт медиазапросы.
- Проверять минимум ширины 1440, 768, 390 и 320 px.
- Избегать горизонтального переполнения, обрезанных кнопок, наложения навигации и скачка размеров медиа.
- Не удалять декоративные элементы, анимации или состояния без проверки их роли и влияния на соседние секции.
- Предпочитать минимальные адресные правки существующим классам вместо дублирования конфликтующих правил в конце файла.

## Внешние ресурсы

Внешние интеграции, включая Kinescope и Telegram, зависят от доступности сторонних сервисов. При локальной проверке отделять сетевые ошибки внешнего сервиса от ошибок HTML/CSS/JS. Не хранить секреты или API-токены в статическом репозитории.

## Документация конкретных версий

Перед изменением версии сначала найти README и специальные инструкции внутри её каталога. Они могут описывать контентные ограничения, визуальные эталоны, список ассетов и отдельные проверки. Общая документация ИИ не заменяет эти инструкции.

- Концепт 4.1: `концеп расстановки/concept-4/v4.1/README.md`, `STYLE_GUIDE.md`, `ASSETS.md`, `ASSET_GAPS.md`, `CHECK_CONCEPT.ps1`.
- Концепт 4.2: соответствующие файлы в `концеп расстановки/concept-4/v4.2/`.
- Концепты 0.1/0.2 расстановок: README и DEVELOPMENT в каталогах версий.
- Концепт 2.1: `ASSETS.md`; концепт 3.1: `CONCEPT-V3.1.md`.
- Лендинг: `концеп лендинга/README.md` и README выбранной версии.

Не переносить правила оформления одного концепта на другой без явного решения: например, стиль-гайд v4.1 — локальный визуальный эталон, а не глобальная дизайн-система всех страниц.

## Автоматизация CI

В репозитории есть GitHub Actions. Перед правками изучать соответствующий workflow, поскольку проверки запускаются не обязательно на каждый файл:

- `.github/workflows/site-browser-audit.yml` — браузерный аудит, доступность и Lighthouse для концепта 4.1; триггер по push ограничен путём v4.1 и указанными инструментами, также доступен ручной запуск.
- `.github/workflows/optimize-portrait-assets.yml` — отдельная автоматизация оптимизации портретных ресурсов; проверять её условия запуска и изменения файлов перед использованием.

Успешный workflow для v4.1 не доказывает, что другая страница проверена. Учитывать фактический охват триггеров и конкретный отчёт запуска.
