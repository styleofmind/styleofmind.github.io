# Документация для ИИ-агентов

## Назначение

Этот каталог описывает, как ИИ-агенту ориентироваться в репозитории Style of Mind, вносить изменения и проверять их без случайного изменения других концептов.

Перед работой прочитать в таком порядке:

1. `../PROJECT_CONTEXT.md` — карта проекта, опубликованные концепты и подтверждённое состояние.
2. `ARCHITECTURE.md` — структура сайта, ответственность файлов и зависимости.
3. `OPERATIONS.md` — безопасный порядок работы, проверки и публикации.
4. `../PLAN.md` — правила выпуска и известные ограничения.
5. README и специальные документы выбранной версии — контентные ограничения, стиль-гайд, ресурсы и локальные проверки.

Если документация расходится с кодом, считать код источником текущего поведения, исследовать расхождение и обновить документацию в том же изменении. Не выдавать предположение за проверенный факт.

## Общее описание

- Репозиторий: `styleofmind/styleofmind.github.io`.
- Основная ветка: `main`.
- Публикация: GitHub Pages.
- Сайт статический: HTML, CSS, JavaScript и локальные изображения; не предполагать наличие серверного приложения или сборщика.
- Корневой `index.html` — каталог концептов, а не одна из страниц концептов.
- Направления и версии независимы: перед редактированием определить точный путь страницы и не переносить изменения между концептами без явного основания.

## Где искать дополнительные правила\n\nУ отдельных версий уже есть собственные README, style guide, карты ассетов и скрипты проверки. Найти документы внутри каталога целевой версии и соблюдать их наряду с этой общей инструкцией. Особенно важно не применять стиль-гайд одного концепта ко всему сайту. Существующие проверки CI также имеют ограниченный охват: успешная проверка одного концепта не означает, что проверены остальные. Подробности см. в `ARCHITECTURE.md`.\n\n## Правила для агента

- Сначала изучить текущий файл и соседние ресурсы; не переписывать страницу целиком ради локального изменения.
- Не редактировать другие версии или концепты «для единообразия» без необходимости.
- Сохранять существующие URL, содержимое, доступность, мобильную навигацию и интеграции, если задача не требует обратного.
- Не добавлять библиотеки, сборщики или инфраструктуру без доказанной необходимости.
- Не генерировать замену реальному фото/постеру, если запрос требует использовать исходный материал.
- Не утверждать, что браузерный вид, тесты или публикация проверены, если проверка фактически не выполнялась.
- При изменении страницы обновлять эту документацию, если изменились структура, поведение, команды проверки или важные ограничения.
